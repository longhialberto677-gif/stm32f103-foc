# 第 3 课：大脑 —— 谁来算、谁来指挥

> 本节包含三个小节：3-1 大脑要多快 / 3-2 为什么必须用 TIM1 / 3-3 引脚怎么分配

---

# 第 3-1 节：大脑要多快？

> 难度 🟡。只回答一个问题：**这块板子的"大脑"为什么需要 72MHz？**

---

## 第 1 步：大脑要干的活

```
每一瞬间，大脑要做 4 件事：
① 采三相电流          → 现在流了多少
② 采转子角度          → 现在转到哪了
③ 算一遍 FOC 的数学   → 该开哪个开关、开多久
④ 改 6 路 PWM         → 真的去开关

然后循环，一秒重复上万次。
```

---

## 第 2 步：一秒要重复几次？

```
一秒 100 次    → 电机转起来一顿一顿的
一秒 20000 次  → 非常顺滑
```

**实际取值：电流环 10kHz ~ 20kHz（每秒 1~2 万次）。**

```
20kHz → 每次间隔 = 1/20000 = 【50 微秒】

这 50 微秒里要完成：采电流 + 读角度 + 算数学 + 改 PWM
而且必须【全部做完】，不能拖到下一次
```

**那"算数学"要花多久？**

```
Clarke 变换：几次乘加
Park 变换：sin/cos + 几次乘加      ← sin/cos 比较贵
两个 PI 调节器：各自几次乘加
反 Park 变换：又是 sin/cos + 乘加
SVPWM：几次乘加和比较

全部加起来大约 【3~5 微秒】（如果用硬件浮点）
```

**结论：**

```
50 微秒的预算，数学只花 5 微秒 → 很宽松 ✅
但如果 CPU 太慢，这 5 微秒会变成 50 微秒 → 直接不够用 ❌
```

> **所以大脑要能"秒算几万次一整套 FOC 数学" → 需要几十 MHz。**

---

## 第 3 步：晶振只有 8MHz，怎么办？

**STM32 内部有个"倍频器"（PLL），能把频率乘上去。**

```
   8MHz 晶振  ──→  [PLL ×9]  ──→  72MHz
```

**打个比方：**

```
晶振 = 一个精确的节拍器（很准，但慢）
PLL = 一个齿轮组（把节拍器"翻倍再翻倍"）
8MHz × 9 = 72MHz = 每秒 7200 万次
```

**为什么不直接装 72MHz 晶振？**

| 晶振频率 | 问题 |
|---|---|
| **72MHz 晶振** | ❌ 高频晶振贵、难做、**不稳定**（容易受干扰） |
| **8MHz 晶振** | ✅ 便宜、稳定、好买 |
| **8MHz + PLL** | ✅✅ **两头的好处都有** |

> **这就是为什么几乎所有单片机都是"低频晶振 + 内部 PLL"。**

---

## 第 4 步：32.768kHz 那个晶振干嘛？

**它跟 FOC 一点关系都没有。**

```
32.768kHz = 走时专用的频率

为什么是这个数？
   32768 = 2 的 15 次方
   → 连续除 2，除 15 次 → 正好得到 1Hz（每秒一次）
   → 天然适合做"秒表"
```

**它是给 RTC（实时时钟）用的：** 记录"现在几点几分"，掉电了靠纽扣电池继续走。

| 晶振 | 频率 | 干什么 |
|---|---|---|
| **X1** | **8MHz** | **PLL ×9 → 72MHz → 跑 FOC** ⭐ |
| **X2** | 32.768kHz | 走时（用不用都行） |

---

## 第 5 步：还有什么在"卡时间"？

**CPU 快不代表就够用，还有三个环节也在抢那 50 微秒：**

| 环节 | 花多久 | 说明 |
|---|---|---|
| **ADC 转换** | 约 3 微秒 | 3 个通道轮流采，每个约 1 微秒 |
| **读编码器角度** | 几十~几百微秒 ❌ | **I2C 慢！** AS5600 走 I2C，这是个大问题 |
| **写 PWM** | 几乎不算 | 直接写寄存器，很快 |

> ⚠️ **注意第二行 —— 这是个真问题：**
> ```
> AS5600 用 I2C 读角度，一次要几十到几百微秒
> 而控制周期只有 50 微秒！
> → 【根本来不及在中断里读】
> → 常见解法：用 DMA 后台读、降低控制频率、或换 SPI 编码器
> ```

---

## 3-1 小结

| 问题 | 答案 |
|---|---|
| 大脑要多快 | **几十 MHz**（秒算几万次 FOC 数学） |
| 为什么 | 电流环 10~20kHz，每次只有 50µs 预算 |
| 72MHz 哪来的 | **8MHz 晶振 × PLL 倍频 9 倍** |
| 为什么不用 72MHz 晶振 | 高频晶振贵、不稳 |
| 32.768kHz 干嘛 | **走时用的，跟 FOC 无关** |
| 还有什么卡时间 | ADC 转换、**I2C 读角度（慢，是个坑）** |

# 第 3-2 节：为什么必须用 TIM1

> 难度 🔴。讲清 FOC 对定时器的三个硬要求。

---

## 第 1 步：要干什么？

```
3 路上管 + 3 路下管 = 6 路 PWM

前提条件：每一路半桥，上管和下管【绝对不能同时开】
```

---

## 第 2 步：为什么不能同时开？

```
   +12V ──[上管 通]──┬──[下管 通]── GND
                     │
                  （电机在这里，但被短路了）

   → +12V 和 GND 之间只剩下两个 MOS 的导通电阻
   → 假设两个加起来 20mΩ
   → 电流 = 12V / 0.02Ω = 【600 安培】❗
```

**600 安培。你的 MOS 额定才几十安培 → 几微秒内炸开。**

> **这在行业里叫"直通"（Shoot-Through），是电机驱动器最常见也最致命的故障。**

---

## 第 3 步：怎么防？（三个层次）

| 层次 | 做法 | 可靠性 |
|---|---|---|
| **① 软件防** | 程序里小心，先关一个再开另一个 | ❌ **不可靠**（中断延迟、bug、跑飞） |
| **② 硬件死区** | 定时器自动插一段"都关"的时间 | ✅ **可靠**（硬件保证） |
| **③ 驱动芯片防** | FD6288T 内部也有死区 | ✅ 双保险 |

> **防直通不能靠软件 —— 因为软件有 bug、有延迟，而直通的后果是"几微秒就炸"。**

---

## 第 4 步：什么是"死区"？

```
【没有死区】❌
上管: ──┐        ┌──
        └────────┘
下管: ────┐    ┌────
          └────┘
        ↑ 重叠了 → 直通炸管

【有死区】✅
上管: ──┐          ┌──
        └──────────┘
下管: ──────┐    ┌──────
            └────┘
          ↑ 死区（两边都关着）
```

**死区要多久？**

```
太短 → 防不住（MOS 还没完全关断）
太长 → 输出失真、效率下降
典型值：几百纳秒 ~ 1 微秒
```

---

## 第 5 步：TIM1 的三个独门本事

### 本事一：互补输出

```
普通定时器（TIM2/3/4）：一个通道只能输出一路
   → 想要上下管两路，得配两个通道，互锁要自己保证 ❌

【TIM1】：一个通道自动输出一对反相波形
   CH1  → 上管
   CH1N → 下管（N = Negative，反相）
   → 硬件保证互锁 ✅
```

### 本事二：硬件死区

```
TIM1 有专门的寄存器（BDTR）设死区时间
   写入一个数 → 硬件自动在 CH1/CH1N 切换处插入空白
   → 【不需要软件干预，永远不会忘记】
```

### 本事三：刹车输入（BKIN）⭐

```
【场景】电机堵转，电流瞬间冲到 30A，程序还在慢慢算 → 来不及

【刹车输入】运放比较器发现过流 → 输出一个电平
   → 直接接到 TIM1 的 BKIN 引脚
   → 【硬件在一个时钟周期内】把 6 路 PWM 全部拉成安全状态
   → 完全不需要 CPU 参与
```

**响应时间对比：**

| 方式 | 响应时间 |
|---|---|
| 软件中断处理 | 几微秒 ~ 几十微秒 |
| **TIM1 刹车（硬件）** | **一个时钟周期（约 14ns）** |

> **差了 1000 倍。而 MOS 的耐受时间是微秒级 —— 这 1000 倍就是"能救"和"炸了"的区别。**

---

## 第 6 步：TIM1 还有什么特别的？

| 特性 | 普通定时器 | **TIM1（高级）** |
|---|---|---|
| **互补输出** | ❌ | ✅ |
| **硬件死区** | ❌ | ✅ |
| **刹车输入 BKIN** | ❌ | ✅ |
| 中心对齐模式 | ✅ | ✅ |
| 触发 ADC（TRGO） | ✅ | ✅ |
| 重复计数器 RCR | ❌ | ✅ |

---

## 第 7 步：所以引脚就定死了

```
TIM1_CH1  →  PA8      TIM1_CH1N →  PB13
TIM1_CH2  →  PA9      TIM1_CH2N →  PB14
TIM1_CH3  →  PA10     TIM1_CH3N →  PB15
```

**设计原理图时的顺序：**

```
① 先定"我要用 TIM1 互补输出"（因为 FOC 需要）
② 再查数据手册，看 TIM1 的 6 个输出在哪些引脚
③ 把这 6 个引脚挑出来接驱动芯片
④ 剩下没用的引脚才分给 LCD / 按键 / 其它
```

> **不是"随便挑 6 个 IO 输出 PWM"。**

---

## 3-2 小结

| 问题 | 答案 |
|---|---|
| 为什么不能上下管同时开 | 直通 = 600A 短路 → 几微秒炸管 |
| 怎么防 | **必须硬件防** |
| 什么是死区 | 上下管切换中间插一段"都关"的空白 |
| 为什么必须 TIM1 | **互补输出 + 硬件死区 + 刹车输入** |
| 刹车为什么重要 | **14ns 响应**，比软件快 1000 倍 |
| 引脚怎么定 | TIM1 输出引脚**固定映射** |

# 第 3-3 节：36 个引脚怎么分配

> 难度 🟡。讲"排座位"的思路。

---

## 第 1 步：手上有什么？

**STM32F103C8T6 一共 48 个脚，去掉电源和地，能用的 IO 大约 37 个。**

**要安排：**

```
【必须有的】
   6 路 PWM、3 路电流采样、1 路温度或母线电压、SWD 调试口
【人机交互】
   LCD 屏（6 根）、4 个按键、2 个 LED、I2C（给编码器）
【通讯】
   串口（USB 调试）、CAN（组网）
```

---

## 第 2 步：原则一 —— 先定"有硬要求的"

| 东西 | 必须在哪些脚 | 为什么 |
|---|---|---|
| **6 路 PWM** | **PA8/9/10 + PB13/14/15** | TIM1 输出**固定映射** |
| **电流采样** | **PA1 / PA2 / PA3** | 见原则二 |
| **SWD 调试** | **PA13 / PA14** | 芯片固定 |
| **串口** | PB6 / PB7 | USART1 固定 |
| **CAN** | PA11 / PA12 | CAN1 固定 |

> **画原理图第一步不是"我要接什么"，而是"芯片强制的约束是什么"。**

---

## 第 3 步：原则二 —— 电流采样为什么用 PA1/PA2/PA3？

### 原因 1：属于同一个 ADC，能"同时"采

```
FOC 需要【同一瞬间】的三相电流（Ia+Ib+Ic=0 要在同一时刻成立）
→ 三个通道必须在【同一个 ADC】上，用"注入组"一次采完
→ PA1/PA2/PA3 正好都在 ADC1 上 ✅
```

### 原因 2：能被定时器"自动触发"

```
FOC 要求在 PWM 的特定时刻采样
→ ADC 要能被 TIM1 硬件触发（不用软件去点）
→ 这个组合支持 ✅
```

### 原因 3（最容易被忽略）：离 VDDA/VSSA 最近 ⭐

```
   8 脚 = VSSA（模拟地）
   9 脚 = VDDA（模拟电源）
   10 脚 = PA0
   11 脚 = PA1
   12 脚 = PA2
   13 脚 = PA3

→ PA0~PA3 就挨着模拟电源脚！
→ 模拟信号走线越短，引入的噪声越少
→ 【离 VDDA 近的引脚，天生适合做模拟输入】
```

> **这是"数据手册里不写，但设计时要想"的知识：引脚分配不只看"功能对不对"，还要看"物理位置好不好"。**

---

## 第 4 步：原则三 —— 剩下的按重要性往外排

```
① 时间敏感的、要频繁读写的 → 放同一边（走线短）
② 慢速的、人机交互的       → 放哪都行
③ 留着几个"备用的"        → 以后加功能用
```

**完整分配表：**

| 功能 | 引脚 | 分类 |
|---|---|---|
| **6 路 PWM** | PA8、PA9、PA10、PB13、PB14、PB15 | 🔴 强制 |
| **三相电流** | PA1、PA2、PA3 | 🔴 强制 |
| **温度/母线电压** | PA0 | 🟠 优先 |
| **SWD 调试** | PA13、PA14 | 🔴 强制 |
| **串口** | PB6、PB7 | 🔴 强制 |
| **CAN** | PA11、PA12 | 🔴 强制 |
| **I2C（编码器）** | PB8、PB9 | 🟠 优先 |
| **LCD** | PA4、PA5、PA7、PB0、PB1、PB10 | 🟢 自由 |
| **4 个按键** | PA15、PB3、PB4、PB5 | 🟢 自由 |
| **2 个 LED** | PB11、PB12 | 🟢 自由 |

> **37 个 IO 里，真正"需要动脑分配"的只有七八个。**

---

## 第 5 步：两个隐藏的坑

### 坑 1：调试口不能乱占 ⚠️

```
PA13 = SWDIO，PA14 = SWCLK（默认是调试口）
如果你把把它们配成普通 IO：
   → 下次就【再也连不上调试器了】
   → 只能靠"BOOT0 拉高进 Bootloader"擦除芯片才能救回来
```

### 坑 2：PB3 / PB4 / PA15 有"第二身份" ⚠️

```
PB3  = JTDO
PB4  = NJTRST
PA15 = JTDI
→ 这三个脚【默认被 JTAG 占用】

它们在你的板子上接了按键。想用它们做普通 IO：
→ 必须先"关闭 JTAG、只留 SWD"

代码里加这一句：
   __HAL_AFIO_REMAP_SWJ_NOJTAG();

不加的话：按键读出来永远是 1（按了也不响应）
→ 你会以为是硬件坏了，其实是软件没配
```

> **STM32 上有一批"复用功能脚"（PA13/14/15、PB3、PB4），默认是调试功能，要手动关掉才能当普通 IO 用。**

---

## 第 6 步：为什么"37 个脚只用了一半"？

```
FOC 的核心需求 = 6 路 PWM + 3~4 路 ADC ≈ 【10 个脚】
剩下 20 多个脚，全给了人机交互。
```

> **FOC 的硬件成本不在"引脚数量"，在"功率级"和"采样精度"。**
> **很多无刷电调只用 20 脚甚至 32 脚的芯片就够了。板子上那么多外设，是为了方便学习和调试。**

---

## 3-3 小结

**三条分配原则：**

| 原则 | 内容 |
|---|---|
| **① 先定硬约束** | TIM1 的 6 个脚、SWD、串口、CAN |
| **② 模拟输入靠 VDDA** | PA0~PA3 挨着 VDDA/VSSA |
| **③ 剩下的按重要性排** | 慢速外设放哪都行 |

**两个隐藏的坑：**

| 坑 | 后果 | 解法 |
|---|---|---|
| **占了 PA13/PA14** | 连不上调试器 | 别占 |
| **用 PA15/PB3/PB4** | 读不出来（JTAG 占着） | 加一句关 JTAG 的代码 |
