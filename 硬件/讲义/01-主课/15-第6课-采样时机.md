# 第 6 课：什么时候采样才准

> 本节包含四个小节：6-1 为什么时机比精度重要 / 6-2 哪个时刻最好 / 6-3 怎么自动启动 / 6-4 时序计算与三个坑

---

# 第 6-1 节：为什么"什么时候采"比"采得准"更重要

> 难度 🟡。先说清一个道理，不涉及公式。

---

## 第 1 步：一个生活里的比方

```
【情况 A】手机像素很高（4800 万），但你按快门晚了一点
   → 拍到的是一滩水
【情况 B】手机像素一般（800 万），但你按快门准时
   → 拍到了漂亮的水花

哪个更有用？→ B
因为"时机错了"，照片根本没有价值 —— 再清晰也没用。
```

**对应到电路：**

| 拍照 | 电路 |
|---|---|
| 像素高不高 | 运放放大得好不好、ADC 精度高不高（第 5 课解决的） |
| **按快门准不准** | **什么时候启动 ADC 采样**（第 6 课要解决的） |

---

## 第 2 步：为什么时机这么关键？

```
PWM 每秒开关 1~2 万次
每次开关的瞬间，电流和电压都在剧烈跳变（微秒级）
   ↓
你如果正好在这一瞬间"按下快门"
   ↓
采到的全是噪声 —— 完全不是真实的电流值
```

---

## 第 3 步：用"闪电"理解

```
【闪电亮起的那一瞬间】
   光线暴增几十倍 → 拍到的全是白光，看不到细节（曝光过度）

【闪电过后 0.1 秒】
   回到正常光线 → 这时拍，能看清 ✅

PWM 开关的那一瞬间就相当于"闪电"：
   叠加在你 10mV 的信号上，变成几百 mV
   → 这时候采 = 拍到白光
```

---

## 第 4 步：算一下有多严重

```
【想测的信号】1A → 采样电阻上 10mV
【开关瞬间的噪声】寄生电感产生尖峰，假设几百 mV

【信噪比】
   正常时刻：10mV / 1mV = 10 倍 ✅
   开关瞬间：10mV / 300mV = 【0.033 倍】❌（噪声是信号的 30 倍）

【换算成电流误差】
   300mV 噪声 → 除以 0.15V/A → 相当于 【2A 的假电流】
   而实际只有 1A
   → 你读到的可能是 3A，也可能是 −1A → FOC 完全失控
```

> **在错误的时刻采样，"精度"毫无意义 —— 因为你测的根本不是电流。**

---

## 第 5 步：时机问题分两个层次

| 层次 | 内容 | 在哪讲过 |
|---|---|---|
| **① 能不能测到** | 只有下管导通时，电流才流过采样电阻 | 第 4-3 节 |
| **② 测得准不准** | 开关瞬间噪声最大 | 本节 |

**两个层次都要满足 → 必须找"同时满足"的那个时刻。**

---

## 6-1 小结

| 问题 | 答案 |
|---|---|
| 为什么时机比精度重要 | 时机错 = 测的不是电流；精度错 = 测的电流不够准 |
| 电机电流为什么难测 | PWM 每秒开关上万个周期，每次都有剧烈跳变 |
| 开关瞬间有多糟 | 噪声可能比信号大 30 倍 → 相当于 2A 的假电流 |
| 时机问题分几层 | ① 能不能测到 ② 测得准不准 |

---

# 第 6-2 节：PWM 周期里，哪个时刻最好？

> 难度 🟡。把"一个周期"切成几段，找出最好的采样点。

---

## 第 1 步：先看"中心对齐"是什么

**定时器内部有个计数器在不停地数数。有两种数法：**

```
【边沿对齐】（普通模式）
   0 → 1 → 2 → ... → 3599 → 突然跳回 0 → 再数
   像爬楼梯：一层层上去，到顶了"啪"地掉回一楼

【中心对齐】（本板用的）
   0 → 1 → ... → 3599 → 3598 → ... → 0 → 再数
   像荡秋千：荡到最高点，再荡回来
```

```
边沿对齐：              中心对齐：
   计数                    计数
    ↑                       ↑
3599┤    ┌────┐          3599┤    ╱╲
    │    │    │              │   ╱  ╲
   0┤──╱      └──→         0┤╱        ╲──→
    锯齿形（爬楼梯）           三角形（荡秋千）
```

**FOC 为什么用中心对齐？三个好处：**

| 好处 | 说明 |
|---|---|
| **① 波形对称** | PWM 两边对称 → 谐波少、电机噪声小 |
| **② 有个天然的"采样窗口"** | 谷底时刻六个管子状态整齐 ← 本节重点 |
| **③ 精度更高** | 一个周期比较两次（上升一次、下降一次） |

---

## 第 2 步：中心对齐下，三个下管什么时候一起导通？

**假设三相占空比分别是 20% / 50% / 80%：**

```
【关键理解】中心对齐下，"下管导通"发生在周期的【两头】

   计数 ╱╲   谷底在两头，峰值在中间
       ╱  ╲
      ╱    ╲
     ╱      ╲
   谷底    峰值    谷底
   → 计数小（谷底附近）→ 下管导通
   → 计数大（峰值附近）→ 上管导通
```

**把三相的下管导通时间画出来：**

```
时间轴：  0%        50%       100%
          ├──────────┼──────────┤

U 下管:  ██░░░░░░░░░░░░░░░░░░██     ← 两头各 10%（共 20%）
V 下管:  █████░░░░░░░░░░░░░░█████   ← 两头各 25%（共 50%）
W 下管:  ████████░░░░░░░░████████   ← 两头各 40%（共 80%）

三个都导通的地方：
         ██                ██
         ↑                  ↑
      开头 10%          末尾 10%
      ← 共同窗口 →       ← 共同窗口 →
```

> ### 🎯 关键结论
> **共同窗口的宽度 = 三相中"最短的那个下管导通时间"。**
> **因为它最短，它导通的时候，另外两个一定也在导通。**

**用"三个人开门"打比方：**

```
甲每天开 2 小时、乙开 5 小时、丙开 8 小时
"三家都开门"的时间 = 【最短的那个，2 小时】
（因为乙和丙在甲开门的这 2 小时里，一定也开着）
```

---

## 第 3 步：为什么"谷底"是最佳采样点？

```
       谷底
        ↓
   ─────┼──┬────────┬──────────────
        │  │        │
        │  │        └─ 窗口结束（最短那相的下管关断）
        │  │
        │  └─ ★最佳采样点★（振铃已衰减，波形稳定）
        │
        └─ 下管刚切换完（这里还在振铃，别采）
```

```
   谷底时刻：t = 0
   振铃衰减：约 200~500ns 后
   最佳采样：t ≈ 0.5µs
   窗口结束：t ≈ 2.5µs（10kHz 时）
```

---

## 第 4 步：⚠️ 窗口够不够宽？

```
【10kHz，占空比限幅 10%~90%】
   周期 = 100µs
   最短的下管导通时间 = 10% → 两头各 5%
   共同窗口 = 5% × 100µs = 【5µs】
   
   扣掉等振铃 0.5µs → 剩 4.5µs
   采 3 个通道要 3µs
   4.5 > 3  ✅ 够用

【如果限幅放到 95%】
   窗口只剩 2.5µs → 2.5 − 0.5 = 2µs < 3µs  ❌ 不够！
```

> **占空比限幅的"度"要算清楚：**
> **限得太松（95%）→ 窗口太窄，采样来不及**
> **限得太紧（80%）→ 输出电压范围不够，电机没劲**
> **10%~90% 是常用折中**

---

## 第 5 步：峰值时刻能不能采？

**不能。回顾第 4-3 节：**

```
【谷底，三个下管全导通】
   电流：电机 → 下管 → 采样电阻 → 地 → 电流【流过采样电阻】→ 能测 ✅
【峰值，三个上管全导通】
   电流：+12V → 上管 → 电机 → 电流【没经过采样电阻】→ 测不到 ❌
```

---

## 6-2 小结

| 问题 | 答案 |
|---|---|
| 定时器有几种数法 | **边沿对齐**（爬楼梯）和**中心对齐**（荡秋千） |
| FOC 用哪种 | **中心对齐**（波形对称 + 天然采样窗口） |
| "下管导通"在哪 | 周期的**两头**（谷底附近） |
| 共同窗口在哪 | 谷底前后，宽度 = **三相中最短的那个下管导通时间** |
| 最佳采样点 | 谷底之后约 **0.5µs**（避开振铃） |
| 为什么不在峰值采 | 峰值时电流不经过采样电阻，**测不到** |
| 窗口够不够 | 10kHz + 限幅 10~90% → 窗口 5µs > 采 3 通道 3µs → **够** |

# 第 6-3 节：怎么让 ADC"自动"在那一刻启动

> 难度 🔴。回答：**软件做不到，那怎么做到？**

---

## 第 1 步：先看"软件采"为什么不行

```c
// 最容易想到的办法
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    HAL_ADC_Start(&hadc1);
    HAL_ADC_PollForConversion(&hadc1, 10);
    ia = HAL_ADC_GetValue(&hadc1);
    // ... 采 ib, ic
}
```

**三个问题：**

```
【问题 1：中断响应延迟不确定】
   定时器到点 → 触发中断 → CPU 要保存现场 → 跳转 → 执行
   → 延迟十几个到几十个时钟周期
   → 如果正在处理另一个中断，还要等
   → 【误差几微秒很正常】

【问题 2：窗口只有几个微秒】
   窗口 5µs，误差 3µs → 一半被误差吃掉 ❌

【问题 3：代码执行时间不确定】
   每次"到点"的时刻都在变 → 【完全无法复现】
```

> **核心问题：软件的执行时刻"不确定"，而你需要的是"确定"。**

---

## 第 2 步：换个思路 —— 让硬件自己去干

```
"什么时候采"这件事，其实【定时器早就知道答案】——
它就是那个在数数的计数器！

那为什么还要"告诉"CPU，再让 CPU 去"告诉"ADC？
→ 直接让定时器【发个信号】给 ADC 不就行了？
```

**像什么？**

```
【软件采】同事要开会了，先打电话给你，你再打电话通知会议室
   → 两层传话，中间还有延迟

【硬件触发】定时器直接拉一根"门铃线"到 ADC
   → 铃一响，ADC 自己就开工了 ✅
```

---

## 第 3 步：这根"门铃线"在哪？—— TRGO

```
   ┌─────────────┐                    ┌─────────────┐
   │   TIM1      │                    │    ADC      │
   │  计数器在数数 │  ── TRGO ──────→   │  触发输入    │
   │             │   （芯片内部连线，   │  一收到就采  │
   └─────────────┘     不用外接）      └─────────────┘
```

**TRGO 可以配置成"在什么时刻发信号"：**

| TRGO 选项 | 什么时候发信号 |
|---|---|
| **UPDATE** | 计数器"更新"时（谷底/峰值） |
| **OC1REF** | 通道 1 比较匹配时 |
| OC2REF / OC3REF | 通道 2 / 3 匹配时 |
| OC4REF | 通道 4 匹配时 |

---

## 第 4 步：⚠️ 中心对齐特有的坑

```
中心对齐时，计数器：0 → 上升 → 3599 → 下降 → 0

【"更新事件"发生在两个地方】
   ① 数到峰值 3599 时
   ② 数回谷底 0 时
   → 一个周期产生【两次】更新事件
   → ADC 会被触发【两次】！❌
```

**后果：一半的触发发生在峰值（那时测不到电流）；或者中断被触发两次，逻辑混乱。**

### 三个解法

| 解法 | 怎么做 |
|---|---|
| **① 用重复计数器（RCR）** ⭐ | TIM1 独有：设"每 N 次更新才真正产生一次事件" |
| **② 用 OC1REF 触发** | 让 ADC 在"通道 1 比较匹配"时触发（可精确指定时刻） |
| **③ 中断里判断方向** | 只处理谷底那次（治标不治本） |

**推荐解法 ①：**

```c
// 中心对齐时一个周期有 2 次更新（峰值 + 谷底）
// RCR = 1 表示"每 2 次更新才产生一次事件" → 只剩一次
htim1.Init.RepetitionCounter = 1;
```

> **这就是第 3-2 节提到的 TIM1"重复计数器"的主要用途。**

---

## 第 5 步：ADC 那边怎么配？

| | **规则组**（Regular） | **注入组**（Injected） |
|---|---|---|
| 优先级 | 低 | **高（可以插队）** |
| 通道数 | 最多 16 个 | 最多 4 个 |
| **适合** | 常规慢速采样（温度） | **需要精确定时的采样** ⭐ |

```c
// 外部触发源 = TIM1 的 TRGO
sConfigInjected.ExternalTrigInjecConv     = ADC_EXTERNALTRIGINJECCONV_T1_TRGO;
sConfigInjected.ExternalTrigInjecConvEdge = ADC_EXTERNALTRIGINJECCONV_EDGE_RISING;
sConfigInjected.InjectedNbrOfConversion   = 3;   // 三个通道
sConfigInjected.InjectedSamplingTime      = ADC_SAMPLETIME_7CYCLES_5;

// 三个通道：PA1 / PA2 / PA3
sConfigInjected.InjectedChannel = ADC_CHANNEL_1;   // U 相
sConfigInjected.InjectedRank    = ADC_INJECTED_RANK_1;
// ... rank 2 和 3

HAL_ADCEx_InjectedStart_IT(&hadc1);
```

**转换完成中断：**

```c
void HAL_ADCEx_InjectedConvCpltCallback(ADC_HandleTypeDef* hadc) {
    uint16_t raw_u = HAL_ADCEx_InjectedGetValue(hadc, ADC_INJECTED_RANK_1);
    uint16_t raw_v = HAL_ADCEx_InjectedGetValue(hadc, ADC_INJECTED_RANK_2);
    uint16_t raw_w = HAL_ADCEx_InjectedGetValue(hadc, ADC_INJECTED_RANK_3);
    
    Ia = to_amps(raw_u);
    Ib = to_amps(raw_v);
    Ic = to_amps(raw_w);
    
    foc_run();      // 立刻算 FOC（在中断里做，保证实时性）
}
```

---

## 第 6 步：完整链路

```
   TIM1 的计数器在数数
      │ 数到谷底（配合 RCR 只触发一次）
      ↓
   TRGO 输出脉冲        ← 硬件自动，不用 CPU
      │ （芯片内部连线）
      ↓
   ADC 注入组           ← 收到触发立刻开始
      │ 依次转换 PA1 → PA2 → PA3
      ↓
   转换完成中断          ← 这时候才需要 CPU
      │
      ↓
   CPU 读三个值 → 算 FOC → 写 CCR 寄存器
```

---

## 第 7 步：⭐ 为什么这样就"精确"了？

```
【软件路径】
   计数器到点 → 中断请求 → CPU 响应（延迟不确定，几~几十周期）
   → 进入中断函数 → 调用 HAL 库 → 启动 ADC
   → 【总延迟：几微秒，且每次都不一样】

【硬件路径】
   计数器到点 → TRGO 输出（1 个时钟周期）
   → ADC 触发输入（1 个时钟周期）→ ADC 开始转换
   → 【总延迟：约 2 个时钟周期 = 28ns，且【每次完全一样】】
```

> **关键不只是"快"，而是"每次都一样"。**
> **电机控制最怕"抖动"（jitter）：硬件触发的抖动是 0，软件触发是几微秒。**
> **几微秒的抖动 → 采样到的电流每次都不同 → FOC 算出乱七八糟的结果。**

---

## 6-3 小结

| 问题 | 答案 |
|---|---|
| 软件采为什么不行 | 中断响应延迟不确定（几微秒），而窗口只有几微秒 |
| 怎么解决 | **让定时器硬件触发 ADC**（TRGO → ADC 触发输入） |
| TRGO 在哪 | 定时器内部输出，芯片内部已连好 |
| 中心对齐的坑 | 一周期产生**两次**更新事件 → 用 **RCR** 去掉一次 |
| ADC 用哪个组 | **注入组** |
| 为什么精确 | 硬件延迟固定约 **28ns**，**抖动为 0** |
| CPU 何时介入 | 只在"转换完成中断"里 |

---

# 第 6-4 节：算一遍完整时序 + 三个实践坑

> 难度 🟡。最实用的一节 —— 讲了就能直接写代码。

---

## 第 1 步：把整条时间线算出来

```
   谷底
    ↓
    ├─① 振铃衰减 0.5µs
    ├─② ADC 采 3 个通道 3µs
    ├─③ 中断响应 + 读值 0.5µs
    ├─④ 算 FOC（Clarke/Park/PI/反Park/SVPWM）3µs
    ├─⑤ 写 CCR 寄存器 0.1µs
    └──────── 总计约 7µs ────────→
```

**两个必须满足的条件（是独立的、两件事）：**

```
【条件 A：采样必须在"共同窗口"内完成】
   窗口 = 5µs（10kHz + 限幅 10~90%）
   采样要 0.5 + 3 = 3.5µs → 3.5 < 5  ✅

【条件 B：整个 FOC 计算必须在【下个周期开始前】完成】
   7µs < 100µs  ✅ 非常宽松
```

| 条件 | 约束什么 | 靠什么保证 |
|---|---|---|
| **A** | 采样在窗口内完成 | **占空比限幅（10~90%）** |
| **B** | 计算在下周期前完成 | **CPU 速度 + 中断精简** |

---

## 第 2 步：★★ 第一个坑：中断里不能做太多事

| 操作 | 花多久 | 说明 |
|---|---|---|
| 读寄存器（直接读） | **几 ns** | ✅ 快 |
| HAL 库函数调用 | **几百 ns ~ 几 µs** | ⚠️ 有参数检查、状态判断 |
| `sinf()` / `cosf()`（软件浮点） | **1~5 µs 每个** | ❌ **F103 没有 FPU，非常慢** |
| `printf()` | **几十 µs** | ❌❌ **绝对不能在中断里用** |

```
【算一下】
   Park + 反 Park 各要 2 个 sin/cos → 4 × 3µs = 【12µs】
   加上 HAL 库开销 → 总共可能 20~30µs
   → 还在 100µs 内，勉强能跑 ✅
   
【但如果 PWM 提到 20kHz（周期 50µs）】
   → 20~30µs 吃掉一半以上
   → 一旦有别的事情插进来 → 【超时】→ 控制周期抖动 → 电机异响
```

### 解法（按性价比排）

| 解法 | 效果 | 难度 |
|---|---|---|
| **① 中断里不用 HAL 库，直接操作寄存器** | 快 10 倍以上 | ⭐⭐ |
| **② 用 CMSIS-DSP 的 `arm_sin_f32()`** | 比标准库快很多 | ⭐ |
| **③ 用查表法**（预先算好 sin 表） | 最快（几 ns） | ⭐⭐ |
| **④ 换 F4/F7**（有 FPU） | 硬件浮点，单周期 | 要改硬件 ⭐⭐⭐ |
| **⑤ 中断只采数据，FOC 放主循环** | 避开时间压力 | 实时性变差 ⚠️ |

### 中断里的"三不三要"

```
❌ 不要：printf / 串口打印、延时函数（HAL_Delay）、复杂数学库、
        动态内存分配（malloc）、while 死等标志位

✅ 要  ：读寄存器、简短的四则运算、查表、写寄存器
```

## 第 3 步：⚠️ 第二个坑：上电初期采到的全是垃圾

```
上电瞬间板子处于"未知状态"：
① 自举电容是空的 → 上管驱动不了
② 电流还没建立 → 采到的可能是随机噪声
③ 编码器还没读到有效角度 → AS5600 上电要几十毫秒初始化
④ 电角度还没对齐 → 不知道转子真实位置

→ 这时候直接进 FOC：
   → 用错误的角度算 → 输出错误的电压矢量
   → 可能【反向猛冲】或【堵转冒烟】❌
```

### 解法：加"启动状态机"

```c
typedef enum {
    STATE_IDLE,          // 空闲（PWM 关闭）
    STATE_CHARGE_BOOT,   // 给自举电容充电
    STATE_ALIGN,         // 电角度对齐
    STATE_OPEN_LOOP,     // 开环强拖
    STATE_CLOSED_LOOP,   // 闭环运行
    STATE_FAULT          // 故障
} state_t;

void motor_task(void) {
    switch (state) {
    case STATE_IDLE:
        if (start_command) { state = STATE_CHARGE_BOOT; boot_timer = 0; }
        break;
    case STATE_CHARGE_BOOT:
        set_duty(0, 0, 0);              // 三相下管全开，给自举电容充电
        if (++boot_timer > 500) state = STATE_ALIGN;   // 5ms @ 10kHz
        break;
    case STATE_ALIGN:
        set_voltage_vector(0.0f, FORCE_VOLTAGE);       // 固定电压矢量
        if (align_done()) { theta_offset = calc_offset(); state = STATE_OPEN_LOOP; }
        break;
    case STATE_OPEN_LOOP:
        if (speed > SWITCH_SPEED) state = STATE_CLOSED_LOOP;
        break;
    case STATE_CLOSED_LOOP:
        foc_run();
        if (fault_detected()) state = STATE_FAULT;
        break;
    case STATE_FAULT:
        pwm_disable();                  // 立刻关断
        break;
    }
}
```

> **状态机是电机控制的"标配"：保证任何时刻都知道自己在干什么，每一步都有明确的进入条件。**

## 第 4 步：⚠️ 第三个坑：占空比一变，触发点还对不对？

```
【触发点是固定的】TIM1 在"计数器到谷底"时发 TRGO
【但窗口是变的】窗口 = 最短那相的下管导通时间
```

```
【正常：20% / 50% / 80%】
   最短 20% → 两头各 10% → 窗口 10µs → 在 0.5µs 处采 ✅
【极端：5% / 50% / 95%】
   最短 5% → 两头各 2.5% → 窗口 2.5µs
   → 采样要 3.5µs（0.5 + 3）→ 【超出窗口】❌
```

**算清楚限幅的"度"：**

```
要求：0.5µs（等振铃）+ 3µs（采样）< 窗口宽度
窗口宽度 = 最短下管导通时间 × 周期 / 2
→ 需要 最短下管导通时间 > 3.5µs × 2 / 100µs = 7%
→ 也就是【最大占空比 ≤ 93%】
```

**两个稳妥做法：**

| 做法 | 说明 |
|---|---|
| **① 限幅 10% ~ 90%** | 窗口 5µs，有 1.5µs 余量，稳 |
| **② 用双 ADC 同时采** | 采样时间 3µs → 1.5µs，可放宽限制 |

## 第 5 步：⭐ 第一版代码参数（照着填）

| 参数 | 建议值 | 理由 |
|---|---|---|
| **PWM 频率** | **10 kHz** | 周期 100µs，时序宽松 |
| **死区时间** | **1 µs** | 偏大更安全（先用示波器确认） |
| **占空比限幅** | **10% ~ 90%** | 保证采样窗口 ≥ 5µs |
| **ADC 采样时间** | **7.5 或 13.5 周期** | 折中精度和速度 |
| **ADC 模式** | **注入组 + T1_TRGO 触发** | 硬件自动 |
| **重复计数器 RCR** | **1** | 中心对齐下只触发一次 |
| **电流环频率** | **= PWM 频率（10kHz）** | 一次中断算一遍 |
| **速度环频率** | **1 kHz** | 在电流环里分频执行 |
| **电流环 PI 初值** | **Kp 小、Ki 更小** | 从很保守开始 |
| **极对数** | **7**（C2208） | 这个不能错 |
| **最大电流限制** | **3A**（相电流峰值） | 先保守，再放开 |

## 6-4 小结

### 两个约束

| 条件 | 靠什么保证 |
|---|---|
| **A. 采样在窗口内完成** | 占空比限幅（10~90%） |
| **B. 计算在下周期前完成** | CPU 速度 + 中断精简 |

### 三个坑

| 坑 | 后果 | 解法 |
|---|---|---|
| **① 中断里做太多事** | 超时 → 控制周期抖动 → 异响 | 不用 HAL 库 / 不用浮点库 / 用查表 |
| **② 上电初期采到垃圾** | 反向猛冲 / 堵转冒烟 | **加启动状态机** |
| **③ 占空比变了窗口也变** | 采到窗口外 | 限幅 10~90%，或双 ADC |
