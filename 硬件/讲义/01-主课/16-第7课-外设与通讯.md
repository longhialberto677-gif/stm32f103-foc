# 第 7-1 节：屏幕、按键、LED

---

## 第 1 步：为什么 FOC 需要一个屏幕？

### 没有屏幕，你只能靠串口打印

```c
printf("Iq=%.2f, Id=%.2f, speed=%d\n", Iq, Id, speed);
```

**问题：**

```
【串口有多慢？】
   115200 波特率 → 每秒约 11520 个字符
   一行 "Iq=1.23, Id=0.05, speed=1800" 约 32 字符
   → 每秒只能打 360 行 → 每行间隔 2.8ms

【但电流环多久跑一次？】
   10kHz → 每 100µs 跑一次
   → 想打印的是"每 100µs 的状态"
   → 但串口只能每 2800µs 打一行
   → 【速度差了 28 倍】

【更糟的】
   printf 本身要几百微秒到几毫秒
   → 放在电流环中断里 → 【直接把控制周期撑爆】
   → 电机立刻抖动、失控
```

### 屏幕好在哪？

```
【屏幕是"并行显示"】
   一次刷一整屏，100ms 刷一次就够了
   → 人眼看起来是"实时"的
   → 而且【完全不占用控制中断】

【关键是"显示状态"，不是"显示数据流"】
   第一行：转速 1800 RPM
   第二行：Iq = 1.23A    Id = 0.05A
   第三行：母线 12.1V    温度 42°C
   第四行：状态 RUN
   → 调 PI 参数时盯着这几行看，比看串口滚屏直观 10 倍
```

> **核心认知：屏幕不是"显示数据的"，是"显示状态的"。**
> **串口适合"记录数据事后分析"，屏幕适合"实时盯状态"。**

## 第 2 步：屏幕怎么接？（SPI + 10 针 FPC）

**FPC1（10 针软排线座）：**

| 引脚 | 网络名 | 作用 |
|---|---|---|
| 1 | LCD_CS | **片选**（低有效） |
| 2 | LCD_BL | **背光**（经三极管 Q3 控制） |

| 4 | LCD_MOSI | **数据**（MCU → 屏幕） |
| 5 | LCD_DC | **数据/命令选择** |
| 7 | LCD_RES | **复位** |
| 8 | GND | 地 |
| 9 | VCC | 3.3V |

**接 MCU：**

| 信号 | MCU 引脚 |
|---|---|
| LCD_CS | PA4 |
| LCD_SCLK | PA5 |
| LCD_MOSI | PA7 |
| LCD_DC | PB0 |
| LCD_RES | PB1 |
| LCD_BL | PB10 |

## 第 3 步：为什么用 SPI，不用 I2C 或并口？

| 方案 | 速度 | 引脚数 | 上拉电阻 | 评价 |
|---|---|---|---|---|
| **I2C** | 400kHz（慢） | 2 | **需要** | ❌ 刷屏会卡 |
| **SPI** | 几十 MHz | 4~5 | **不需要** | ✅ **本板的选择** |
| **并口** | 快 | 十几根 | 不需要 | ❌ 太占引脚 |

**SPI 的三个好处：**

```
① 快：几十 MHz，刷屏不卡
② 省引脚：4~5 根就够
③ 不需要上拉（推挽输出，天然能拉高拉低）
```

**代价：SPI 只写不读（多数 LCD 不需要读）；多一根 DC 线（区分命令/数据）。**

---

## 第 4 步：为什么背光要用三极管？

```
【背光 LED 需要多少电流？】
   4 颗白光 LED 并联，每颗约 15mA → 总共 60mA
【STM32 单引脚能出多少？】
   约 20mA
→ 超了 3 倍 ❌
```

**所以用三极管"以小控大"：**

```
VCC ── 背光LED ── C(集电极)
                   [Q3 NPN]
        GND ────── E(发射极)
PB10 ──[R14 1kΩ]── B(基极)
```

```
【基极电流】= (3.3V − 0.7V) / 1kΩ = 【2.6mA】 ✅ 远低于 20mA 上限
【集电极电流】= 【60mA】← 从 VCC 来，不关 IO 的事
```

> **IO 只出 2.6mA，就指挥了 VCC 输出 60mA。**
> **而且可以用 PWM 控制基极 → 调节背光亮度。**

## 第 5 步：4 个按键

| 按键 | MCU 引脚 | 上拉电阻 |
|---|---|---|
| KEY1 | **PA15** | R17 = 4.7kΩ |
| KEY2 | **PB3** | R22 = 4.7kΩ |
| KEY3 | **PB4** | R24 = 4.7kΩ |
| KEY4 | **PB5** | R28 = 4.7kΩ |

### 为什么必须上拉？

```
机械按键只有"通/断"两个状态
→ 断开时引脚是【浮空】的
→ 浮空引脚电压不确定，会被噪声干扰
→ 程序读到随机跳变

【上拉电阻】把引脚默认拉到高电平：
   没按 → 读到 1；按下 → 读到 0  ← 低电平触发
```

### ⚠️ PA15 / PB3 / PB4 有"第二身份"

```
PA15 = JTDI，PB3 = JTDO，PB4 = NJTRST
→ 这三个脚【默认被 JTAG 占用】

想用它们做普通 IO，代码里必须加：
   __HAL_AFIO_REMAP_SWJ_NOJTAG();   // 关掉 JTAG，保留 SWD

不加的话：按键永远读不出来（一直是 1）
→ 你会以为硬件坏了，其实是软件没配
```

### 三种消抖方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **硬件 RC 消抖** | 不占 CPU | 多 2 个元件/键，参数固定 |
| **软件 delay 消抖** | 零成本 | **阻塞 CPU** |
| **定时器状态机消抖** ⭐ | 不阻塞、参数可调 | 稍复杂 |

```c
// 定时器状态机消抖（实际产品标准做法）
void key_scan_tick(void) {      // 每 1ms 调用一次
    for (int i = 0; i < 4; i++) {
        uint8_t now = read_key_pin(i);
        if (now != key_last[i]) {
            key_count[i] = 0;
            key_last[i] = now;
        } else if (key_count[i] < 20) {
            key_count[i]++;
            if (key_count[i] == 20) {      // 稳定 20ms
                key_event[i] = (now == 0) ? PRESSED : RELEASED;
            }
        }
    }
}
```

## 第 6 步：2 颗 LED

| LED | 颜色 | 限流电阻 | MCU 引脚 |
|---|---|---|---|
| LED1 | **红** | R26 = **1kΩ** | **PB12** |
| LED2 | **绿** | R30 = **470Ω** | **PB11** |

### 为什么阻值不同？

```
红灯正向压降约 1.8V，绿灯约 2.2V
→ 要让两颗看起来一样亮，需要不同限流电阻

【验算】
   绿灯：(3.3 − 2.2) / 470Ω ≈ 【2.3mA】
   红灯：(3.3 − 1.8) / 1kΩ  = 【1.5mA】
   都远低于 20mA 上限 ✅
```

### ⭐ 推荐用法

```
绿灯常亮  = 系统就绪、PWM 未使能
绿灯闪烁  = 正在运行
红灯亮    = 【故障锁存】⚠️
```

**为什么"红灯当故障锁存"特别有用？**

```
【场景】电机突然停了，你不知道为什么
   · 程序跑飞了？硬件保护触发了？编码器坏了？过流了？

【如果红灯亮并锁存】
   → 至少知道"是保护动作"，不是"程序崩了"
   → 这一颗灯能省几个小时排查时间
```

# 第 7-2 节：USB 和 CAN

---

## 第 1 步：USB Type-C + CH340N（调参通道）

| 元件 | 型号/值 | 作用 |
|---|---|---|
| USB1 | HC-TYPE-C-16P-01E | 16 针 Type-C 母座 |
| **R15 / R12** | **5.1kΩ** | **CC1 / CC2 下拉** ⭐ |
| F1 | SMD0603-075-6 | VBUS → +5V 的自恢复保险丝 |
| U4 | CH340N | USB 转串口 |
| C18 / C20 | 100nF | V3 / VCC 退耦 |

### ⭐ 为什么 5.1kΩ 是"必须"的？

```
Type-C 充电器/电脑的 CC 引脚在检测："对面插的是什么设备？"
   → 它测量 CC 上的下拉电阻
   
5.1kΩ 下拉  →  "这是需要供电的设备（Sink）" → 输出 5V ✅
不接下拉    →  很多充电器【理都不理你】❌
```

**CC1 和 CC2 都要接：**

```
Type-C 线正反插时会交换 CC1/CC2
→ 你永远不知道插的是哪一面 → 两个都要 5.1kΩ 下拉
```

### ⚠️ CH340N 的 V3 脚（经典易错点）

| 型号 | V3 脚怎么接 |
|---|---|
| **CH340G**（5V 版） | 接 **100nF 到地**，**不能接电源**（内部自产 3.3V） |
| **CH340N**（3.3V 版，本板） | **接 VCC（3.3V）** + 100nF 去耦 |

**接错轻则通讯不稳，重则烧芯片。换型号务必查这一脚。**

### 串口接法（注意交叉）

| CH340N | 网络名 | MCU 引脚 | MCU 复用功能 |
|---|---|---|---|
| TXD（6 脚） | CH340 TX | **PB7** | USART1_**RX** ✅ |
| RXD（7 脚） | CH340 RX | **PB6** | USART1_**TX** ✅ |

> **记法：发送方的 TX 必须接到接收方的 RX。**
> **图上标的网络名是站在 CH340 角度命名的，很容易看反。**

### ⚠️ 数据线上没有串联 22Ω 电阻

```
通常 USB 的 D+/D− 会串 22Ω 做阻抗匹配和限流
本板没装 → 能工作，但 USB 频繁掉线时
→ 【加两颗 22Ω 串联电阻是第一个可以试的办法】
（同时检查 D+/D− 是否走了差分对、等长）
```

## 第 2 步：CAN（TJA1050T）

| 元件 | 型号/值 | 作用 |
|---|---|---|
| U6 | TJA1050T/CM,118 | CAN 收发器 |
| R25 | **120Ω** | **终端电阻** ⭐ |
| D7 | PESD2CAN | 总线 ESD/浪涌保护 |
| C25 | 100nF | 退耦 |
| CN2 | HC-1.25-2PWT（2 针） | 1=CAN_L，2=CAN_H |

| TJA1050T | 网络名 | MCU 引脚 | 说明 |
|---|---|---|---|
| TXD(1) | CAN TX | **PA12** | CAN1_TX ✅ |
| RXD(4) | CAN RX | **PA11** | CAN1_RX ✅ |
| S(8) | GND | — | **接 GND = 高速模式** |

### ⭐ 为什么 CAN 两端必须各有一个 120Ω？

```
CAN 用【差分信号】，物理上是【特征阻抗 120Ω 的双绞线】

信号传播时，如果末端阻抗不匹配：
   → 能量会【反射回来】→ 和原信号叠加 → 波形振铃
   → 接收端把振铃当成"多个位" → 【数据错乱】❌

并联 120Ω：
   → 末端阻抗"看起来"和线一样 → 匹配
   → 能量被完全吸收 → 没有反射 ✅
```

### ⚠️ 本板的实际使用问题

```
【CAN 规范】最远两端各一个 120Ω，中间节点不接
【本板】R25 = 120Ω 直接焊死，不可断开

→ 双节点实验（本板 + USB-CAN 分析仪）：正好两个，匹配 ✅
→ 挂 3 个以上节点：板载 120Ω 与其他并联 → 阻抗被拉低
   （3 × 120Ω = 40Ω）→ 可能通讯不稳 ⚠️

改进：把 R25 改成跳线/拨码选择
```

## 第 3 步：为什么电机驱动板要配 CAN？

| | UART | **CAN** |
|---|---|---|
| 拓扑 | 点对点 | **总线（一条线挂十几个节点）** |
| 抗干扰 | 弱（单端） | **强（差分 + CRC + 自动重发）** |
| 距离 | 几米 | **几十米（低速上百米）** |
| 多主 | 不支持 | **支持（硬件优先级仲裁）** |

**实际场景：**

```
· 机器人/机械臂：一条 CAN 挂 6 个关节电机，同步运动
· 电动滑板/平衡车：上报转速、电流、温度、故障码
· 四足/无人机：CAN 的【硬件仲裁】保证急停指令第一时间抢占总线
```

> **CAN 的核心优势：硬件级的可靠性和实时性。**
> **每帧有 CRC → 出错自动重发；冲突靠 ID 优先级仲裁（ID 越小优先级越高）→ 不需软件处理。**

**保护元件：**

```
D7 = PESD2CAN：CAN 可能引到板外走几十米线
   → 静电、浪涌、雷击感应会耦合进来
   → 专为 CAN 设计的双路 TVS
   → 【只要接口引到板外，就必须有保护】

没有共模电感：
   严格设计会串共模电感抑制共模噪声
   本板没装 → 定位是"板内/短距离通讯"
   → 要拉到恶劣电磁环境 → 加共模电感是第一步改进
```

# 第 7-3 节：⚠️ 编码器接口与三个隐患

## ⭐ 编码器接口：就是 CN1

**板子上给编码器留的接口是 `CN1`：**

```
CN1（型号 HC-1.25-4PWT，1.25mm 间距 4 针卧贴座）

   引脚 1 → VCC      (3.3V)
   引脚 2 → PB9      (I2C SDA)  ← 图上直接标着 "I2C SDA"
   引脚 3 → PB8      (I2C SCL)  ← 图上直接标着 "I2C SCL"
   引脚 4 → GND
```

**和 AS5600 的需求对照：**

| AS5600 需要 | 板子提供 | 对不对 |
|---|---|---|
| 电源 | VCC 3.3V | ✅ |
| 地 | GND | ✅ |
| SDA | PB9 | ✅ |
| SCL | PB8 | ✅ |

**PB8/PB9 是 STM32F103 的 I2C1 标准引脚（I2C1_SCL / I2C1_SDA），硬件配置现成。**

### 接线表

```
   AS5600 编码器              板子 CN1
   ─────────────              ─────────
      VCC (3.3V)  ──────────── 引脚 1 (VCC)
      SDA         ──────────── 引脚 2 (PB9)
      SCL         ──────────── 引脚 3 (PB8)
      GND         ──────────── 引脚 4 (GND)
   （如果还有 DIR / PWM / OUT 之类的线 → 先不用）
```

### 需要处理的三个实际问题

| # | 问题 | 怎么解决 |
|---|---|---|
| **① 接头形状** | 板子是 1.25mm 4P 插座，电机可能是散线/杜邦头 | 压一个 1.25mm 4P 头，或直接焊线到焊盘 |
| **② 线数可能多于 4** | AS5600 还可能有 DIR/PWM 输出 | 只用 VCC/GND/SDA/SCL 四根 |
| **③ 上拉电阻**（见下） | 图上 CN1 附近**没有任何电阻** | 确认 AS5600 小板是否自带 |

## 隐患 1：I2C 没有上拉电阻 🔴（最重要）

### 问题

```
I2C 是【开漏输出（Open-Drain）】总线：
   器件只能"拉低"，不能"拉高"
        ↓
如果没有外部上拉：
   → 总线永远是低电平或浮空
   → 【永远无法产生高电平】
   → I2C 完全无法通讯 ❌
```

### 三种可能，必须确认

| 可能 | 怎么判断 | 结论 |
|---|---|---|
| **① AS5600 小板上自带 4.7kΩ 上拉** ⭐ 很常见 | 看电机尾部那块小板，找两颗连到 VCC 的电阻 | **直接能用** ✅ |
| **② 板子 PCB 上有但原理图漏画** | 在 EasyEDA 里搜 `PB8`/`PB9` 看连了几个元件 | 确认一下 |
| **③ 真没有** | 同上 | **必须外接两颗 4.7kΩ** |

### 怎么接（如果是情况 ③）

```
   VCC (3.3V) ──┬──[4.7kΩ]── I2C_SDA (PB9)
                │
                └──[4.7kΩ]── I2C_SCL (PB8)

   → 都接到 VCC（3.3V），不是 VCCA
```

### ⚠️ 为什么不能用 STM32 的内部上拉？

```
STM32 内部上拉约 40kΩ —— 太弱
   → 上升沿变慢（RC 时间常数大）
   → 400kHz Fast Mode 下波形变"圆角" → 通讯误码 ❌
【I2C 标准上拉是 2.2kΩ ~ 4.7kΩ，必须外置】
```

### 上电第一件事：I2C 扫描

```c
// 看总线上有哪些设备 —— 一次性确认接线、上拉、芯片是否正常
for (uint8_t addr = 1; addr < 128; addr++) {
    if (HAL_I2C_IsDeviceReady(&hi2c1, addr << 1, 2, 10) == HAL_OK) {
        printf("发现设备：0x%02X\n", addr);
    }
}
// AS5600 的地址是 0x36
// 打印出 0x36 → 编码器通了 ✅
```

### 这件事为什么重要？

```
C2208 + AS5600 是"闭环位置控制"的黄金组合：
   · 磁编码器、12 位分辨率
   · 绝对角度（不需要上电找零）
   · 无接触、寿命长

【但 I2C 不通 → 只能用"无感 FOC"】
   → 靠反电动势估算角度
   → 低速性能差很多、零速无法定向
   → 【白白浪费了这颗 AS5600 的全部价值】
```

### AS5600 特有的三个硬件注意点

| 注意点 | 说明 |
|---|---|
| **磁铁要正对中心** | 偏心会导致角度非线性 |
| **距离 2~3mm** | 太远信号弱，太近饱和 |
| **附近不能有铁磁材料和强磁场** | 螺丝、铁壳都会干扰 |
| **有内部滤波延迟** | 几十~几百 µs（这就是"来不及在中断里读"的原因，见第 3-1 节） |

### 电机上编码器的抗干扰

```
电机运行时 PWM 产生强电磁干扰，而编码器线就在电机旁边
→ I2C 是"高阻抗 + 慢速"总线 → 【最容易受干扰】
→ 表现：角度读数偶尔跳变、或通讯直接断掉

三个防护：
   ① 线尽量短、远离电机相线
   ② 用双绞线（SDA/SCL 绞在一起，或各自和一个 GND 绞）
   ③ 在 CN1 旁边加 100nF 滤波电容（可选）
```

|---|---|---|
| **看状态** | LCD（SPI 10 针） | 屏幕是"显示状态"的，不是"显示数据流"的 |
| **调参数** | 4 个按键 | 上拉 + 软件消抖；**PA15/PB3/PB4 要关 JTAG** |
| **看故障** | 红/绿 LED | **红灯当故障锁存灯最有用** |
| **连电脑** | Type-C + CH340N | **5.1kΩ CC 下拉必须**；V3 接 3.3V |
| **组网** | TJA1050T | 120Ω 终端电阻"两端各一个" |
| **接编码器** | **CN1（4 针 I2C）** | **必须解决上拉问题** |

### 三个隐患（按优先级）

| 优先级 | 隐患 | 影响 |
|---|---|---|
| 🔴 **高** | **I2C 没有上拉** | **编码器用不了 → 只能用无感 FOC** |
| 🟠 中 | CAN 终端电阻焊死 | 多节点组网时阻抗失配 |
| 🟡 低 | USB 无 22Ω 串联电阻 | USB 可能不稳 |
